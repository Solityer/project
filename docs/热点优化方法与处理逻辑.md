# 热点优化方法与处理逻辑

## 1. 项目当前 formal 约束

- 唯一 formal note 只有 `GAT-ZKML-多层多头.md`。
- 严禁修改 `GAT-ZKML-多层多头.md`。
- 严禁违背 formal note 中已经收敛的协议语义、proof schema、transcript 顺序、serializer / parser 结构、verifier equations。
- 只能做实现层优化、hotspot 迁移、cache / layout / memory / execution placement 优化、backend 内部执行细化。
- benchmark 只接受 `full-dataset + warm + verified + 官方 artifact 真源`。
- 唯一官方指标只有：
  - `commitment_time_ms`
  - `prove_time_ms`
  - `verify_time_ms`
  - `proof_size_bytes`
- `context_build_ms`、各类 profiling 子项可以用来定位热点，但不能脱离四项官方指标单独作为 retained 依据。

## 3. 当前热点总览

### 3.1 总体结论

- verify 已经不是当前第一主矛盾。
- 当前真正需要继续压的是 `ppi / ogbn-arxiv` 的 `commitment_time_ms` 与 `prove_time_ms`。
- 两条大图的瓶颈都集中在 trace 生成与动态 commitment，不在 formal 语义层。

### 3.2 PPI 当前热点

- 主体矛盾在 `trace_generation_ms` 与 `commit_dynamic_ms`。
- 细分上重点看：
  - `state_machine_trace_ms`
  - `psq_trace_ms`
  - `hidden_softmax_chain_trace_ms`
  - `witness_materialization_ms`
  - `dynamic_domain_convert_ms`
- PPI 是 `multi_graph_batch`，不能把单图优化路径直接当成默认结论。
- 本轮复核后要额外记住一点：`ogbn-arxiv` 的 `static_context_cache=miss` 不是 PPI 多图 cache 路线带出来的连带副作用；单图 ogbn 正式路径本来就不走持久 static context cache。

### 3.3 ogbn-arxiv 当前热点

- 主体矛盾仍然是 `prove_time_ms`，并且 `trace_generation_ms` 体量很大。
- 细分上重点看：
  - `state_machine_trace_ms`
  - `psq_trace_ms`
  - `lookup_trace_ms`
  - `route_trace_ms`
  - `witness_materialization_ms`
  - `dynamic_domain_convert_ms`
- `context_build_ms` 虽大，但不进入官方四项记账，因此只能作为实现观察项。

## 4. 已保留的优化方法

### 4.1 单图 `q_new selector fast path`

- 方法：在 `graph_count == 1` 时，对 `q_new` 为 `0/1` 的状态递推使用简化执行路径。
- 适用条件：只允许单图路径启用，多图 batch 禁用。
- 作用位置：`PSQ` 与 `state machine` 的前缀状态构造。
- 保留原因：
  - 对 `ogbn-arxiv` 的单图正式路径有真实 proving 收益。
  - 不改变 formal 语义，只是同一逻辑下的执行层 gating。
  - 已验证多图 `ppi` 不能直接把这条路当默认主线，因此保留为“单图启用，多图禁用”。

### 4.2 CUDA size-aware hotspot 路由

- 方法：在 `full_gpu` 内部按 workload 大小决定是否把 CUDA 可获益的 Fr 域热点交给 GPU。
- 适用条件：`full_gpu` 后端内部执行选择。
- 作用位置：barycentric 权重、shared weighted evaluation、shared tau-evaluation batch、lookup histogram 等。
- 保留原因：
  - 不改变语义，只改变执行放置位置。
  - 能保持 `full_gpu` 是完整正式后端，而不是伪 GPU 辅助路径。

### 4.3 ogbn-arxiv 单图 `c_max / PSQ` warm state-vector cache

- 方法：对 `volatile_large_trace` 下的 `c_max` 与 `PSQ` 状态向量开放 warm-up 到 measured run 的进程内缓存复用。
- 适用条件：
  - 单图正式路径。
  - `whole_graph_single`。
  - 只对 `:cmax` 与 `:psq:` 这两类状态向量生效。
- 不适用条件：
  - 不对 PPI 多图 batch 开放。
  - 不扩展到 route trace、lookup artifacts 等更大对象。
- 直接作用：
  - 压低 measured run 的 `state_machine_trace_ms`。
  - 压低 measured run 的 `psq_trace_ms`。
  - 主要改善 `prove_time_ms`，不是重新定义 commitment 口径。
- 保留原因：
  - 不改变 proof 内容，只复用 warm-up 已构造过的同一执行层状态。
  - `proof_size_bytes` 不变，`verified` 保持为 `true`。
  - 对 ogbn-arxiv 的 CPU / GPU 正式 proving 都形成明显净收益。

## 5. 已回退但有价值的优化方法

### 5.1 PPI 多图 `dst group` 直接前缀状态构造

- 方法：尝试在 PPI 多图 batch 中，不再通过 `q_new` 通式递推，而是按 `edge_groups_by_dst` 直接构造 `c_max / PSQ`。
- 原始动机：直接压 `state_machine_trace_ms` 与 `psq_trace_ms`。
- 实验结论：本轮已回退。
- 回退原因：
  - 正式 `ppi` warm 结果没有形成净收益。
  - `commitment_time_ms` 与 `prove_time_ms` 都没有比 accepted baseline 更好。
  - 该路线说明“多图 batch 的真实热点虽然也在状态向量，但简单替换递推形态并不能自动得到收益”。
- 保留价值：
  - 说明多图路径不能只看代数等价，还要看真实 cache / branch / warm cache 行为。
  - 后续如果继续碰 PPI，多半要从更上游的数据布局、materialization、dynamic commitment 热点入手，而不是只改前缀状态公式。

### 5.2 PPI 多图 `shared tau evaluation cache`

- 方法：只在 `multi_graph_batch` 下，对 dynamic commitment 里来自 shared column 的 `tau evaluation` 做 warm-up 到 measured run 的进程内复用，目标是直接压 `dynamic_domain_convert_ms`。
- 原始动机：PPI 当前 `commit_dynamic_ms` 的主体已经不是 `MSM`，而是 shared column 在 measured run 里重复做整域 `tau evaluation`。
- 局部实验结果：
  - `PPI CPU commitment_time_ms` 一度从 `3510.734` 压到约 `1839.992`。
  - `PPI CPU prove_time_ms` 一度压到约 `5447.121`。
  - `PPI GPU commitment_time_ms` 一度压到约 `1836.901`。
  - `PPI GPU prove_time_ms` 一度压到约 `5437.707`。
- 本轮最终结论：有价值，但本轮未 retained，已回退。
- 回退原因：
  - 进入 global regression control 后，`ogbn-arxiv` 的 GPU 正式单图重跑出现了远超软保护门槛的异常退化，且 manifest 中出现 `static_context_cache=miss`。
  - 从代码 gating 看，这条方法只在 `multi_graph_batch` 下生效，因此该单图异常大概率不是这条 PPI 方法本身的语义回归；但在没有把全局 official truth 重新同步干净之前，不能把这条 patch 留在主线里。
  - 为了避免“PPI 本地大赢，但正式主表与真源不同步”的状态，这轮必须诚实回退。
- 保留价值：
  - 它证明了 PPI 多图真正值得继续深挖的方向不是 `state_machine` 公式本身，而是 dynamic commitment 前的 shared column 扫描与复用。
  - 下轮如果继续打 PPI，`dynamic_domain_convert_ms` 仍然是第一优先级之一。

### 5.3 ogbn-arxiv 单图 `binding trace` warm cache

- 方法：只在 `volatile_large_trace` 单图正式路径里，让 `binding trace` 的小对象缓存从 warm-up 复用到 measured run。
- 原始动机：`ogbn-arxiv` 当前真正进入官方四项账本的 prove-side 压力仍在 `trace_generation_ms`、`witness_materialization_ms`、`dynamic_domain_convert_ms`，而 `binding trace` 本身是复用价值高、对象体积小的候选。
- 本轮 CPU 正式实验：
  - `commitment_time_ms` 从当前代码态隔离重跑的 `19242.307` 压到 `17696.225`。
  - `prove_time_ms` 从当前代码态隔离重跑的 `81761.300` 压到 `64667.800`。
- 本轮 GPU 正式实验：
  - `commitment_time_ms` 为 `17768.484`。
  - `prove_time_ms` 为 `68019.118`。
- 本轮最终结论：有明显 CPU 价值，但不能 retained，已回退。
- 回退原因：
  - 它没有同时满足双后端 retained gate。
  - 相对 accepted GPU baseline `17541.068 / 65736.261`，GPU 正式结果退化到 `17768.484 / 68019.118`，总账为负。
  - 因此这条方法不能只凭 CPU 获益进入正式主线。
- 保留价值：
  - 说明 `volatile_large_trace` 下并不是所有 warm cache 都会误伤 formal 路径；小对象 binding cache 在 CPU 上确实能把单图 proving 压回 64 秒级。
  - 但要想 retained，后续还必须单独解释并压住 GPU 上的对应回退。

## 6. 当前执行逻辑总流程

1. 读取正式配置、checkpoint bundle、真实图数据。
2. 构建 formal context。
3. 构建 trace，并在过程中记录 `trace_generation_ms` 与细分热点。
4. 对动态 witness 列做 commitment，并在过程中记录 `commit_dynamic_ms` 与子项。
5. 构建 quotient、domain opening、external opening。
6. 完成 prove，得到 `prove_time_ms`。
7. 运行 verify，得到 `verify_time_ms`。
8. 导出 proof、manifest、benchmark artifacts。
9. 只有在 retained patch 成立时，才刷新 README、tests、`latest.json / latest.csv / summary.md`。
10. 如果本轮没有新增 retained patch，但 rejected 实验覆盖了 ignored 的 official warm manifests 或 benchmark 汇总，就必须先把它们恢复到 accepted baseline，再做 CPU / GPU formal verification。

## 7. `full_cpu` 与 `full_gpu` 的执行区别

- 两者共享完全相同的 formal semantics。
- 两者共享相同的 transcript 顺序、proof schema、verifier equations、artifact contract。
- `full_cpu` 是默认完整执行路径。
- `full_gpu` 是同一 formal 主线下的完整后端，只把可获益 hotspot 交给 CUDA。
- `full_gpu` 的差异是执行层差异，不是第二套语义，不是第二套 proof。
- 因此任何 retained patch 都必须满足：
  - CPU formal correctness 不变。
  - GPU formal correctness 不变。
  - proof contract 不变。
  - `proof_size_bytes` 稳定。

## 8. PPI 当前主瓶颈与处理逻辑

### 8.1 当前认识

- PPI 的关键身份是 `multi_graph_batch`，不是单图。
- 当前真正拖慢的是：
  - `trace_generation_ms`
  - `commit_dynamic_ms`
  - `witness materialization`
  - `state_machine / PSQ / hidden_softmax_chain`
- 其中 `route_trace_ms` 现在已经不是主战场。

### 8.2 当前处理逻辑

- 不把 `ogbn-arxiv` 单图 retained 方法直接搬到 PPI。
- 每次只推进一个明确候选补丁。
- 如果补丁不能在 `PPI commitment/prove` 上形成清晰净收益，就立即回退。
- 本轮已经确认：`static_context_cache=miss` 与 PPI 多图路线不是直接因果，因此后续查 PPI 不要再把 ogbn 单图 miss 当成第一嫌疑点。
- 多图路径优先考虑：
  - materialization 复用
  - 大列布局
  - 动态 commitment 前的共享数据复用
  - 能否减少重复扫描和不必要对象构造

## 9. ogbn-arxiv 当前主瓶颈与处理逻辑

### 9.1 当前认识

- `ogbn-arxiv` 是单图正式路径，已经可以使用单图 `q_new selector fast path`。
- 现在继续限制它的，主要不是 verify，而是 prove 主链路：
  - `trace_generation_ms`
  - `state_machine_trace_ms`
  - `psq_trace_ms`
  - `lookup_trace_ms`
  - `route_trace_ms`
  - `dynamic_domain_convert_ms`

### 9.2 当前处理逻辑

- 沿单图 retained 路线继续深挖，不另起第二语义。
- 优先找 warm-up 与 measured run 之间可以安全复用、且不会改变 proof 的对象。
- 对象优先级要继续区分：
  - 小对象 `binding trace` 可以继续研究。
  - `route / lookup / 大矩阵` 这类大对象不能无约束放开。
- 如果某个缓存对象很大但数量可控，并且只影响单图大实例的执行层，可以考虑做受控保留。
- 如果某个方法虽然能加速 wall clock，但只改善 `context_build_ms`，则不能单独作为 retained 理由。

## 10. 每一轮优化的 retained / reverted 结论

### 10.1 retained

- 方法：ogbn-arxiv 单图 `c_max / PSQ` warm state-vector cache。
- 适用条件：只在 `volatile_large_trace` 的单图正式路径中，对 `:cmax` 与 `:psq:` 状态向量启用。
- formal 影响：无语义变化，无 transcript 变化，无 proof schema 变化，无 verifier equations 变化。
- 最终结果：
  - full_cpu `ogbn-arxiv commitment_time_ms`：`17459.511 -> 17569.742`，小幅变差。
  - full_cpu `ogbn-arxiv prove_time_ms`：`67405.878 -> 65329.058`，明显改善。
  - full_gpu `ogbn-arxiv commitment_time_ms`：`17490.679 -> 17541.068`，小幅变差。
  - full_gpu `ogbn-arxiv prove_time_ms`：`67975.010 -> 65736.261`，明显改善。
  - `proof_size_bytes`：CPU/GPU 都保持 `21361`。
- 保留理由：
  - 主目标格子里，`ogbn-arxiv prove` 在 CPU 和 GPU 都明显为正收益。
  - `commitment_time_ms` 的退化幅度小于 `prove_time_ms` 的收益幅度，总账明显为正。
  - `verify_time_ms` 有波动，但没有构成“收益不够却明显恶化”的回退条件。

### 10.2 reverted

- 方法：PPI 多图 `dst group` 直接前缀状态构造。
- 适用条件：PPI `multi_graph_batch`。
- 最终结果：
  - 正式 `ppi` warm 没有形成正收益。
  - `state_machine_trace_ms / psq_trace_ms` 没有按预期下降到可保留区间。
  - `commitment_time_ms / prove_time_ms` 没有优于 accepted baseline。
- 回退理由：
  - 该方法虽然代数上可行，但真实实现账本上没有赢。
  - 多图 batch 的热路径更依赖上游布局、对象复用和 commitment 前处理，不适合只通过改前缀状态构造方式来保留。

- 方法：PPI 多图 `shared tau evaluation cache`。
- 适用条件：只作用于 `multi_graph_batch` 的 dynamic commitment shared column。
- 最终结果：
  - 历史局部正式 run 曾经把 `PPI` 主目标两格明显压到 retained 候选区间。
  - 但本轮在当前正式代码态下重新隔离验证，没有复现可保留的正式收益。
- 回退理由：
  - 代码因果链已经查清：`ogbn-arxiv` 的 `static_context_cache=miss` 不是这条 PPI 路线直接造成的。
  - 但是当前代码态的正式隔离 rerun 没有给出可 retained 的 `PPI commitment/prove` 净收益，因此它依然不能进主线。

- 方法：ogbn-arxiv 单图 `binding trace` warm cache。
- 适用条件：`volatile_large_trace` 单图正式路径，只缓存小型 `binding trace` 对象。
- 最终结果：
  - CPU `ogbn-arxiv` 明显转正，`prove_time_ms` 压到 `64667.800`。
  - GPU `ogbn-arxiv` 没有守住 retained gate，`prove_time_ms` 回到 `68019.118`。
- 回退理由：
  - 这轮的 retained 标准是 CPU/GPU 都不能破坏 formal 主线下的目标总账。
  - 既然 GPU 主目标格子净退化，这条方法必须诚实回退。

### 10.3 本轮最终收口

- 本轮没有新增 retained gain。
- `PPI multi_graph shared tau evaluation cache` 与 `ogbn-arxiv binding trace warm cache` 都已完整回退，正式代码态不保留实验性实现。
- 本轮额外完成了一次真源恢复：把被实验覆盖过的 official warm manifests 与 `latest.json / latest.csv / summary.md` 恢复回 accepted baseline，避免 README、tests 与 ignored artifacts 再次分叉。
- 在真源恢复后，CPU formal suite 与 GPU formal suite 都重新通过，说明当前仓库正式态仍然满足 one-formal-logic、full_cpu、full_gpu 与 proof contract 约束。

## 11. 下轮优先级建议

- 如果 PPI 继续优化，优先回到 `dynamic commitment + witness materialization + layout` 这条线，不要重复把“按组直接改前缀状态”当默认解。
- PPI 下轮第一优先级建议直接围绕 `shared column` 的 `tau evaluation / dynamic_domain_convert_ms` 做更严格的 batch-only 方案，并在进入 retained 判定前先确认不会把单图 `ogbn-arxiv` 的官方真源同步打乱。
- 如果 ogbn-arxiv 继续优化，优先沿“单图大实例的小对象 cache + dynamic commitment”这条线继续压 `prove_time_ms`，其中 `binding trace` 是一个已经证明 CPU 有值、但 GPU 还没收住的候选方向。
- 下轮进入任何 retained 判定前，先快照 accepted manifests 与 benchmark 汇总，避免 rejected 实验再次把 ignored official truth 覆盖掉。
- verify 继续保持观察，不作为默认主战场。
- 所有文档更新继续只维护这一份文件，不新增第二份热点记录文件。
